# Development postmortem

1. **SDK version assumptions broke the first MCP integration test.** Installed MCP 2.3 renamed FastMCP to MCPServer and response fields to snake_case. The real subprocess test exposed the mismatch. Inspecting installed signatures and updating imports/fields fixed it; direct dependencies are now pinned. A function merely named an MCP tool would not have caught this.
2. **Scrapling's minimal install was insufficient.** Its standard HTTP fetcher imported curl_cffi and internal browser-support packages. Installing the documented fetcher extras fixed imports. Only Scrapling Fetcher/Spider APIs are used; no standalone browser scraping was introduced.
3. **Source availability constrained the data plan.** Mytek returned 403; Tunisianet's terms forbid catalog reproduction. Neither was bypassed. Spacenet supplied public structured product metadata and permitted crawling with a ten-second delay. A first laptop attempt failed closed on a transient robots DNS timeout. Slow, transparent collection was preferable to fabricated counts.
4. **The API key did not imply usable credits.** A small live OpenAI test returned HTTP 429, no credits remaining. An explicitly labeled manual structured-input mode now demonstrates the same transaction workflow without claiming a live AI result.
5. **Windows pipe encoding damaged UI emojis.** The first Streamlit rendering test found invalid question-mark icons. Material icon names and ASCII labels fixed rendering. The installed AppTest API also resolved relative paths against the test file, requiring an absolute entrypoint path.
6. **Email needed a safer local launcher.** Existing configuration pointed to an external SMTP host while EMAIL_MODE was sandbox. The service correctly rejected it. The local launcher now explicitly uses loopback SMTP and preserves the user's .env. A real local SMTP test and an end-to-end real-catalog smoke order verified delivery without external messages.
7. **LangSmith indexing is asynchronous.** Immediate read-after-write returned 404. A later retrieval through the current SDK verified the trace. The UI handles unavailable/unindexed trace links without failing procurement.
8. **Docker and browser automation were unavailable.** Docker CLI existed but its daemon pipe was absent; the browser access host was unavailable. Native Python startup, API tests, Streamlit AppTest, and local SMTP supplied practical verification. Docker startup and browser visual review are documented as unverified rather than passed.

Lessons: verify actual interfaces early, test the protocol boundary, keep account/service availability separate from implementation quality, preserve uncertain stock and specifications as unknown, and report measured evidence with its limitations. The offline evaluation validates deterministic control paths; live language understanding still needs a funded integration run.
